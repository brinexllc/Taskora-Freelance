# Рабочие процессы панели Taskora

## Модели и сохранение истории

Миграция `0019_admin_panel_workflows` добавляет поля без изменения ID, договорных сумм, подписей, денежных проводок и путей существующих файлов.

| Модель | Назначение |
| --- | --- |
| `Project.moderation_status` | `pending`, `approved`, `rejected`, `hidden`; независим от статуса сделки |
| `Project.moderation_version` | Версия текста и решения модерации |
| `Project.moderation_pending_public` | Новая публикация допускает постмодерацию; восстановление ранее скрытой публикации ждёт отдельной проверки |
| `Profile.public_hidden` | Публичный профиль остаётся скрытым после разблокировки до проверки администратора |
| `AccountRestriction` | Основание блокировки, администратор, снимок числа обязательств, дата снятия |
| `AdminObligation` | Отдельная задача на каждый незакрытый договор и вывод заблокированного пользователя |
| `ModerationDecision` | Неизменяемая через интерфейс история решений: объект, автор, основание, до/после |
| `ContentReport` | Жалоба на профиль, заказ, отзыв или сообщение; исходные доказательства и ссылка на предыдущее обращение |
| `ProposalReport` | Существующие жалобы дополнены стадией, решением и администратором |
| `SupportTicket`, `SupportMessage` | Обращение пользователя, ссылка на договор/спор и переписка с администрацией |
| `SkillVerification` | Навык, доказательство, статус, проверивший администратор, решение, срок действия |
| `DisputeNote` | Служебная заметка или запрос доказательств конкретной стороне; заметки не входят в пользовательскую переписку |
| `DisputePreview` | Снимок расчёта, основание, сторона, версии договора/спора; действует 15 минут |
| `AdminCommand` | Постоянный UUID запроса, отпечаток входных данных и результат выполненного действия |
| `AuditLog` | Дополнительные поля `reason`, `before`, `after`, `request_id`, `operation_id`, `outcome` |

Исторические JSON-отметки навыков сохраняются в журнале и переводятся в очередь проверки, если сопоставляются с навыком. Сами по себе они больше не создают публичное подтверждение. Публичный список `verified_skills` вычисляется по действующим одобрениям, выбранным навыкам и срокам действия. Объединение навыков снимает доверие к исходному подтверждению и возвращает его на проверку.

## Пользовательские маршруты

Все изменения требуют обычной пользовательской браузерной сессии и CSRF. Списки и карточки доступны только автору обращения или заявки; подмена ID чужого объекта не раскрывает данные.

| Маршрут | Операция |
| --- | --- |
| `GET/POST /api/reports/` | Мои жалобы / новая жалоба: `object_type`, `object_id`, `reason` |
| `GET /api/reports/{id}/` | Состояние собственной жалобы |
| `GET/POST /api/support-tickets/` | Мои обращения / новое обращение: `subject`, `text`, необязательный `contract` |
| `GET /api/support-tickets/{id}/` | Состояние собственного обращения |
| `GET/POST /api/support-tickets/{id}/messages/` | Переписка / ответ пользователя |
| `GET/POST /api/skill-verifications/` | Свои заявки / доказательства навыка: `skill`, `evidence_type`, `description`, `evidence_url` или `evidence_file` |
| `GET /api/skill-verifications/{id}/download/` | Защищённая выдача собственного доказательства |
| `POST /api/projects/{id}/resubmit-moderation/` | Отправить скрытый/отклонённый заказ на повторную проверку |

Во frontend обращения доступны через **Поддержка** в кабинете, заявки навыков — в настройках профиля. Жалобы доступны из карточек профиля, заказа, отзыва и сообщений. Ответы администрации подписаны «Администрация Taskora» и доставляются во внутренние уведомления.

## Административные ограничения

Вход в рабочие процессы проходит через `execute_command`: сервер повторно проверяет активного администратора, MFA и действующую `BrowserSession`. Финансовые операции, блокировки, отзыв доступа, отмена договора и раскрытие материалов требуют свежего подтверждения безопасности.

Формы сохраняют UUID запроса и отпечаток открытой карточки. Повтор с тем же UUID и тем же содержанием возвращает результат; другой запрос с этим UUID получает HTTP 409. Если карточка изменилась после открытия формы, операция отклоняется до изменения данных. Основание и результат записываются в одной транзакции с изменением.

Блокировка отзывает браузерные сессии, устаревшие и scoped-токены. Она не распределяет escrow и не отменяет договоры. Разблокировка требует нового входа и отдельного восстановления публичного контента. Последнего администратора заблокировать нельзя.

Исправление email/телефона снимает подтверждение изменённого контакта и погашает старые проверочные коды. Баланс, доверенные признаки и административные права через редактор профиля не изменяются.

Спор проходит стадии `opened → evidence_collection → admin_review → resolved`. Из рассмотрения можно вернуться к сбору доказательств. Закрытый спор остаётся историей; связанное обращение не запускает повторный расчёт.

Окончательный расчёт выполняет существующий `escrow.resolve_dispute` через проверенный `DisputePreview`. Повторно проверяются версии, состояние спора, резерв, комиссия и основание. Полная выплата, возврат и раздел используют единый финансовый сервис. Служебная заметка меняет версию спора и делает прежний предпросмотр неактуальным.

Администратор может предложить поправки к условиям, но не подписать их за участника. Поправки применяются только после отдельных подтверждений обеих сторон. Отмена до финансирования запрещена при ненулевом резерве или наличии факта финансирования.

Модерация сообщений хранит оригиналы и не меняет `read_at`. В пользовательском API скрываются текст, имя файла и текст последнего сообщения; скачивание скрытого вложения участником закрыто. Администрация получает оригинал только через защищённый просмотр с основанием.

## Проверки

`marketplace.test_admin_panel_workflows` проверяет блокировку и сохранность денег, последнего администратора, сброс контактных подтверждений, пост- и премодерацию, чтение скрытого заказа участником, расчёт спора и повтор UUID, устаревший предпросмотр, неизменность отзывов и сообщений, снятие доверия после слияния навыков, изоляцию обращений, отмену до финансирования и отсутствие фиктивных подписей.
