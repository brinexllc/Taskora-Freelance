## Правила комиссии

Уточнение владельца после первоначального выпуска: тариф утверждён — 5% с исполнителя, 0% с заказчика. Default теперь `5`; локальный `.env` обновлён. Production-переменная, если она явно равна `0`, требует отдельного изменения при выпуске. Значение `8` вводится только отдельным решением. Порядок исправления ошибочных договоров до резервирования и выпуска: [обновление](figma-commission-update.md).

Ставка фиксируется при создании договора, включая ещё неподписанные договоры. Отклик её не фиксирует. Заказчик резервирует S, комиссия удерживается с присуждённой исполнителю суммы G при одном окончательном расчёте. F округляется один раз `ROUND_HALF_UP` до 0.01; N=G−F, R=S−G. Старые плановые `fee_amount`, `net_amount` и текст условий сохраняются.

`PlatformFee.contract` и `settlement_reference` уникальны. Балансы, пользовательские движения, PlatformFee, фактические суммы, закрытие резерва и аудит сохраняются одной транзакцией. Договор блокируется первым, профили — по user ID. Пополнение, резервирование и вывод не создают повторного удержания TASKORA.

## Manifest и импорт

[catalog-v1.json](../backend/marketplace/catalog-v1.json) содержит явные slug, canonical name, labels для ru/uz/uz-cyrl/en, aliases и категории навыка. Категории: development, mobile, automation, design, marketing, writing, qa-support, other. Testing и серверные навыки входят в qa-support; «Другое» использует общий поиск.

Идентичность сравнивается через NFKC, casefold и схлопывание пробелов; значимые символы сохраняются. Реестр SkillAlias включает также канонические имена, поэтому пространства имён не конфликтуют. Известные синонимы объединяются с переносом связей; исходный ID остаётся неактивным со ссылкой на замену. React Native сохраняется отдельно. Analytics и Strategy сохраняются с отчётом для ручного решения. Импорт и объединение не присваивают Verified Skill; прежние подтверждённые названия сохраняются для проверки.

Повторный seed не перезаписывает ручные имена, labels, деактивации, удалённые администратором алиасы или связи уже инициализированных записей. Пользователи, заказы и балансы импортом не создаются.

## API

Общий префикс — `/api/`. Существующие права доступа сохранены.

| Маршрут | Контракт |
| --- | --- |
| `GET directory/` | Без изменения: `{categories:[{slug,name}], skills:[name]}`. |
| `GET catalog/?lang=ru` | `{taxonomy_version:"catalog-v1", categories:[{id,slug,name,label,active,sort_order,icon_key}]}`. Только активные записи, стабильный порядок, other последним. |
| `GET skills/` | `{count,next,previous,results:[{id,slug,name,label,labels,category_slugs,active}]}`. Дополнительный `labels` позволяет переводить уже выбранные теги без потери выбора. Параметры: search, category, lang, page, page_size (до 50). Поиск: точное совпадение, префикс, подстрока; затем каноническое имя и ID. |
| `GET platform-fees/` | `currency`, `freelancer_fee_percent`, `customer_fee_percent`, `calculation_basis`, `policy_version`, `payer`, `rounding`, `precision`. Деньги и проценты — строки. Пример версии: `commission-v1:5.00`. |
| `POST proposals/`, `POST proposals/{id}/accept/` | Новый клиент передаёт `expected_fee_policy_version`; поддерживается также `expected_fee_percent`. При несовпадении — 409, `code:"FEE_POLICY_CHANGED"`, `detail`, `policy`, `errors:{}`. Клиентские итоговые суммы/ставки не принимаются. Старый клиент может опустить ожидание; договор создаётся без подписей для отдельного подтверждения. |
| Projects | `category` остаётся slug; `category_label` локализуется. `skills` остаётся списком имён. Добавлены `skill_ids` для записи, `skill_details` для чтения, `skills_unspecified` (default false). Оба способа записи навыков одновременно разрешены только при одинаковом наборе. |
| Profiles и `auth/me/` | Сохраняются имена навыков; добавлены ID и skill_details. Выбор навыка не создаёт справочную запись. Отсутствующие поля PATCH сохраняются; уже привязанный неактивный навык можно сохранить, новое назначение запрещено. |
| `GET projects/`, `GET profiles/` | Сохранён `skill=<canonical name or alias>`, добавлены повторяемые `skill_id` и `skill_match=all|any` (default all). Для заказов сохранён `category=<slug>`. Неизвестные категории, навыки и режимы — 400, отсутствие результатов — 200. |
| Contracts | Плановые `fee_amount`, `net_amount`; `fee_policy_snapshot`; nullable `actual_fee_amount`, `actual_net_amount`; фактические G/R в `released_amount`, `refunded_amount`. NULL не подменяется нулевым расчётом. |
| Wallet entries | Дополнительно `contract_actual_fee_amount`, строка или NULL; выплата и комиссия остаются отдельными строками. |

Язык по умолчанию ru; допустимы ru/uz/uz-cyrl/en. Fallback label: выбранный язык → ru → name. В auth/me используется сохранённый язык профиля. Техническое name и сохранённые тексты договоров не переводятся.

Черновик разрешает 0–30 навыков. Для публикации нужны активные навыки либо `skills_unspecified=true` с пустым списком. Остальные проверки бюджета, срока, категории и доступа сохранены. Историческое чтение неактивных записей доступно.

## Проверка миграции и сверка

Проверена резервная копия локальной `backend/local-mvp.sqlite3` и приватных файлов в `.taskora-qa/commission-backup/`. SQLite `integrity_check` вернул ok. Исходные данные: 2 профиля, 1 проект, 1 связь проекта с навыком, 0 договоров и 0 движений кошелька. Сравнение копии до/после подтвердило сохранность профилей, проекта и M:N; после seed — 8 активных категорий и 90 канонических навыков, включая один прежний дополнительный навык. Повторный импорт ничего не создаёт, отчёт ручной проверки пуст. Миграции и seed применены также к локальной базе.

Наличие завершённых договоров в production не проверялось. Исторические финансовые сценарии проверены на искусственных данных: backfill требует совпадения события settled, подтверждённого резерва, ESCROW_RELEASE, PLATFORM_FEE и REFUND. Плановая комиссия доказательством не считается. При недостатке данных сохраняется NULL и выдаётся отчёт; балансы не меняются. Восстановленные записи имеют source=backfill; повторный запуск не создаёт дубли.

Результаты и диагностические файлы находятся в игнорируемой `.taskora-qa/`: `postgres-tests.log`, `sqlite-final-tests.log`, `final-catalog-dry-run.json`, `final-catalog-apply.json`, `final-catalog-repeat.json`, `final-fee-reconciliation.json`, `migration-comparison.json`.

## Проверки

Финальный прогон: PostgreSQL 17.11 — 89/89 тестов успешно; SQLite — 88 успешно и 1 ожидаемый пропуск конкурентного теста. Проверки Django check и makemigrations --check --dry-run также прошли. PostgreSQL запущен локально только для тестов, на 127.0.0.1:55441, из официального [архива EDB](https://www.enterprisedb.com/download-postgresql-binaries), без установки службы и без обращения к production. Настройка `TEST_DATABASE_URL` отделена от рабочего `DATABASE_URL`. Тест конкурентного расчёта запускает два соединения и проверяет одну выплату, одну системную комиссию и один прирост баланса; на SQLite он намеренно пропускается.

Frontend: lint, TypeScript и production-сборка прошли. Пять контрольных примеров предварительного расчёта и отклонение неверной ставки также прошли. Предварительная комиссия использует BigInt, контрольный случай 0.10 при 5% даёт 0.01. В браузере на отдельной тестовой базе проверены поиск по алиасу, сохранение выбора при смене категории/пустом поиске, публикация без стека, фактический частичный расчёт, языки и темы. Тестовые аккаунты и деньги не добавлялись в обычную локальную базу.

## Выпуск владельцем

1. Создать backup рабочей БД и приватных файлов, проверить восстановление и инвентаризацию на копии.
2. На тестовой копии выполнить `check`, `makemigrations --check --dry-run`, `migrate --plan`, затем `migrate --noinput` до 0011.
3. Выполнить `seed_catalog --dry-run`; разобрать неизвестные категории и неоднозначные навыки. После проверки — `seed_catalog --apply`.
4. Выполнить `backfill_platform_fees --dry-run`. Проверить подтверждающие движения и расхождения; `--apply` восстанавливает только доказанные факты без изменения балансов. `fee_report` отдельно показывает оборот G, суммы договоров, комиссию, возвраты и выполненные выводы.
5. Выпустить совместимый backend, затем frontend. Проверить health, directory, catalog, skills, platform-fees, проекты, профили, auth/me и основной цикл сделки.
6. После объявления тарифа и подтверждения коммерческих условий установить `PLATFORM_FEE_PERCENT=5` и перезапустить backend. Проверить публичную политику и снимок нового договора. Переход на 8 выполняется таким же отдельным решением, без пересчёта старых договоров.

Команды запускаются через `python backend/manage.py <команда>` в согласованном backend-окружении. Для тестов PostgreSQL явно задаётся `TEST_DATABASE_URL` на отдельную тестовую БД; обычный DATABASE_URL тестами не используется. Схема изменяется при pre-deploy, не в Docker build. После новых финансовых записей применяется совместимый выпуск или исправление вперёд, без удаления истории и без `--fake`.

Production-деплой, реальные платежи, банковские расходы, налоги и коммерческое включение тарифа не выполнялись. Финансовый журнал — управленческий учёт комиссии до расходов, а не доказательство чистой прибыли или банковского escrow.
