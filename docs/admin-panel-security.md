# Доступ владельца к панели

Панель находится по адресу `/admin/`. Владелец должен быть активным пользователем с обоими признаками `is_staff` и `is_superuser`. Режим заказчика/исполнителя, разрешения обычного staff и API-токены административных прав не дают. Проверка применяется и к прямому backend, и к запросам через Next.js.

Первую учётную запись создают в доверенной серверной консоли из корня проекта:

```sh
python backend/manage.py platform_admin owner --create --email owner@example.com --reason "Первичное подключение владельца платформы"
```

Команда запросит новый пароль скрытым вводом и проверит его стойкость. Для автоматизированной доверенной консоли пароль можно передать через переменную окружения `TASKORA_ADMIN_PASSWORD`; аргумент `--password-env` задаёт другое имя переменной. Значение пароля не передают аргументом команды и не включают в отчёты. Созданная запись не получает доступ к данным панели до подключения TOTP.

Откройте `/admin/`, введите логин и пароль. Если MFA ещё не настроена, форма направит в `/dashboard?view=settings`: подключите приложение-аутентификатор, подтвердите одноразовый код, затем вернитесь в панель. Обычный вход после подключения требует пароль и свежий TOTP. Повторное использование принятого кода отклоняется. SMS и внешний почтовый сервис для TOTP не требуются.

Финансовые действия, блокировки, раскрытие материалов и публикации требуют повторного подтверждения пароля и нового TOTP. В разделе безопасности подтверждение действует 300 секунд. Для новых переключателей и запуска денежных операций диалог появляется автоматически, затем продолжает сохранённое действие; состояние объекта проверяется снова. Обычные настройки и остановка новых денежных операций не требуют повторного пароля внутри действующей MFA-сессии. Административная сессия прекращается после 30 минут бездействия либо 12 часов с момента создания, даже при непрерывной работе.

При утрате MFA восстановление выполняют в той же доверенной консоли:

```sh
python backend/manage.py platform_admin owner --recover-mfa --reason "Восстановление после подтверждённой утраты MFA"
```

Команда устанавливает новый пароль, отзывает старые браузерные сессии, API-токены и незавершённые проверки контактов/сброса пароля. `--recover-mfa` дополнительно удаляет прежний фактор, после чего потребуется новое подключение. Без этого параметра действующий фактор сохраняется. Обычный сброс пароля не сбрасывает MFA. Создание и восстановление записываются в аудит как операции доверенной консоли, без пароля и секрета TOTP.

Из панели нельзя выдать права администратора, изменить пароль или удалить учётную запись. Блокировка последнего активного администратора запрещена, включая параллельные запросы. Пользовательские формы отвергают финансовые, административные и доверенные признаки. Старые Django-формы также ограничены: баланс и признаки проверки не меняются редактированием профиля, финансовые и аудиторские записи доступны только для чтения или специализированных действий.

Приватные файлы выдаются через действие с основанием, свежим подтверждением и аудитом. Куки, пароли, токены, ключи и полные реквизиты не выводятся в карточках и вложенных данных журнала. Next.js передаёт CSRF и идентификаторы запроса/операции; список допустимых внешних Origin задаётся `CSRF_TRUSTED_ORIGINS`, произвольные `X-Forwarded-*` не расширяют его. За HTTPS, Secure/HttpOnly cookies и production-настройки отвечает существующая конфигурация окружения.

Автоматические проверки: `test_admin_panel_security.py` проверяет доступ, сроки сессий, MFA, файлы, восстановление и прежние формы; `test_admin_panel_concurrency.py` проверяет реальные блокировки PostgreSQL; `frontend/scripts/server-proxy.test.mjs` проверяет границу Next.js.
